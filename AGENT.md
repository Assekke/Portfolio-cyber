Портфолио для киберспортсмена.
Файлы: index.html — разметка, styles.css — вид, script.js — логика.
Требования к функциям — в папке specs/. Описание для людей — в README.md.

Правила

Только HTML, CSS и JavaScript в этой папке. Без npm, библиотек и внешних ресурсов.

Данные храни в браузере (localStorage). Ничего не отправляй в интернет.

Интерфейс на русском языке, подписи короткие и понятные.

Кнопки и поля не меньше 44px, страница работает на телефоне шириной 375px.

Делай только то, о чём попросили. Работающие функции не ломай.

Проверки Git разрешены. Коммит и отправка в удалённый репозиторий — только по подтверждению пользователя согласно разделу «Git».

После тестов покажи результат и дождись моей проверки. Самостоятельно не коммить и не публикуй.

Даты — в формате ДД.ММ.ГГГГ. Никнеймы и названия команд сохраняй в исходном написании. Не выдумывай статистику и достижения.

Разделы файла: Для кого и зачем; Что должно быть; Примеры; Ограничения; Готово, когда.

## Git
- Перед работой выполни git status. Проверки без изменения репозитория (status, diff, log, remote -v, branch --show-current) разрешены без отдельного подтверждения. Если есть незакоммиченные изменения, которые не относятся к уже согласованной работе, сообщи о них и спроси, что с ними делать; не включай их в коммит автоматически.
- Сделал один согласованный шаг или файл требований и проверил сам — остановись. Покажи изменённые файлы (git status --short) и напиши, что мне проверить руками. Дождись результата моей проверки, затем спроси: «Коммитим?»
- «Да» или «делай» подтверждает только действие из последнего вопроса. Ответ на «Коммитим?» разрешает git add с явным списком проверенных файлов и git commit -m "<короткая подпись по-русски>". Затем остановись; push этим ответом не разрешён.
- Для push укажи целевой удалённый репозиторий и получи отдельное подтверждение. Если я явно прошу «коммит и пуш сразу» для проверенных изменений в известном репозитории, выполни оба действия последовательно без повторного вопроса.
- Перед разрешённым push проверь git remote -v. Если список пустой — push пропусти и скажи об этом. Если push просит upstream — выполни git push -u origin <текущая ветка> только для согласованного репозитория. Если push отклонён или просит вход — остановись и покажи ошибку целиком.
- Любая команда git не выполнилась — остановись, покажи ошибку целиком и ничего не обходи.
- Я ответил «нет» или описал ошибку — исправь, проверь снова и дождись моей повторной проверки. Без моего подтверждения не коммить.
- Завершение проверки, коммита или push не разрешает переход к следующему шагу или находке. Дождись отдельного подтверждения на следующий шаг.
- Историю не переписывай: без git reset --hard и git push --force.

## Большая функция
- Если функцию нельзя сделать и проверить за один раз, добавь в конец specs/NNN раздел «Шаги»: 3–6 шагов по порядку, у каждого [ ].
- У каждого шага: что появится на экране и проверка на 2–3 действия руками.
- Первым ставь шаг, на котором строятся остальные.
- Делай только один шаг за раз. Сделал — отметь его [x] в разделе «Шаги» и действуй по разделу «Git».
- README.md обновляй после последнего шага. Новые файлы тестов не создавай.

## Исправления
- Я прошу «Проверь проект» — код не меняй. Пройди по требованиям в specs/ и по разделу «Как проверить». Поищи ошибки на пустом, нулевом, очень длинном и повторном вводе, после перезагрузки страницы и на ширине 375px. Создай specs/NNN-proverka.md с разделом «Находки»: 5–8 пунктов с [ ], сначала ошибки. У каждой находки: тип (ошибка / правка / рефакторинг), «что сделать → что ожидается → что происходит» и как мне проверить руками. Пиши простыми словами: что нажать и что я увижу, без названий функций. В чём не уверен — так и напиши.
- Я прошу исправить находку или сам описал ошибку — сначала найди причину в коде и назови её одной-двумя фразами. Потом исправь только её, остальное не трогай.
- После исправления проверь по шагам находки, что ошибки больше нет, проверь раздел «Как проверить». Находку отметь [x] перед коммитом.
- Ошибка в поведении, которого нет в «Примерах» specs/NNN, — допиши туда пример с моими числами.
- Не получилось с двух попыток — остановись и напиши, что пробовал. Наугад не чини.
- Мелкая правка вида (цвет, размер, подпись, отступ) — не новая функция: файл требований не нужен, «делай» не жди. Сделай и действуй по разделу «Git».
- Рефакторинг — это большая функция: «Шаги» в specs/NNN. Поведение и вид страницы не меняй; у каждого шага проверка теми же числами, что в «Как проверить».
- Отменить сохранённый коммит — только через git revert и только после моего подтверждения этого действия. Отправка отмены через push подтверждается по разделу «Git».
